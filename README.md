## Verification

F19/F29 now use the current content-size category for key, hint, candidate, and host-app text. Candidate row and top-bar heights follow the scaled font metrics. Key text caps to the actual row height, and alternate hints yield to a larger primary label only when both lines physically cannot fit; the alternate accessibility action remains available. The requested keyboard height preserves the saved 90–220% setting but is capped to the lesser of 60% of the owning scene's safe-area height or that height minus a 44-point editable host strip. This independent scene cap can reduce the visible height even at 220%; it grows again on a larger scene without changing the setting. A floating host may assign still less height, which is budgeted from actual root bounds. When More cannot show one candidate row while preserving usable keys, it temporarily uses the space below the candidate bar as a scrollable selection view and hides the keys; tapping More again restores them. A compact Globe remains in the top bar when iOS requires an input-mode switch key. A host smaller than the top bar plus one candidate row cannot display a whole expanded row. Source and hosted geometry tests do not establish installed-keyboard behavior on iPad or in every orientation.

The branch adds a shared Xcode scheme, hosted XCTest cases and a macOS simulator workflow. CI uses Xcode 26.2 and a simulator created for that job, saves logs and an `.xcresult`, and does not alter production signing or entitlements. A passing simulator suite establishes only the behaviors it asserts. Extension-host integration, accessibility appearance, App Group access, screenshots and performance measurements need separate evidence before their corresponding items can close.

The letter keyboard keeps comma and period as primary composition keys and shows [ and ] hints on them for long press and VoiceOver alternate actions. This leaves their widths unchanged at compact sizes. The symbols page continues to insert literal brackets with an empty composition. These paths need native simulator and installed-extension checks before F30 is complete.

Candidate VoiceOver labels retain the visible value while value text adds code and exact/prefix or homophone status. Hints describe the context-dependent action and only advertise numeric/Space shortcuts the controller actually implements: digits 0–9 map to candidate indexes 0–9, exact candidates only in letters mode, and indexes 10+ have no numeric shortcut. Ordinary non-reverse symbol modes do not advertise digit selection. Reverse lookup distinguishes exploring homophones from committing a phrase base; active homophone candidates identify their pronunciation codes. This requires native VoiceOver validation before F18 can close.

The host test panel now constrains its scroll viewport to the keyboard layout guide and keeps the focused field or multiline caret in view on focus, selection, layout, and size changes. The hosted scene test verifies real system-keyboard occlusion on an iPhone-sized view, then compact viewport and caret geometry. It also checks that manually scrolling to lower actions is not undone while a field remains focused. Actual installed-extension rotation and iPad checks are still required.

The Return key now labels itself from the host's return-key trait. It commits an active raw composition on the first press; a subsequent press sends one newline through `UITextDocumentProxy`. The proxy API does not expose a host submit or next-field command, so Search/Send/Next outcomes require installed-extension tests in actual host fields. They are not established by the fake-proxy tests.

Numeric settings accept stored NSNumbers containing finite whole values. Values below or above the supported range clamp to its boundary, including zero and negative values; missing, wrongly typed, fractional, or non-finite values use the documented default. Keyboard layouts accept only the three current values and the two known legacy values until host-app migration consumes them. Both reads and writes apply the same limits.
